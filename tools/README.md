# tools

跨实验的小工具。只放**与具体实验无关**的东西——每个实验自己的分析脚本（`summarize.py` /
`compare.py`）留在各自的实验目录里。

| 工具 | 作用 | 用法 |
|---|---|---|
| `peek_results.py` | 逐条明细人工验货（对/错标记、真值对比） | `python tools/peek_results.py results/.../hf_nf4_b1.jsonl --wrong` |
| `verify_refactor.sh` | 结构回归自检：路径锚点 / 结果完整性 / 残留引用 / 工作区卫生 | `bash tools/verify_refactor.sh` |

## verify_refactor.sh 检查什么

改动目录结构后跑一次（不占 GPU，约 1 分钟）：

1. **路径锚点 + 结果目录镜像规则**能否正确解析
2. 三组实验的分析脚本能否跑通
3. **结果文件完整性**（哪些配置的数据缺失）
4. **报告数字与结果文件的一致性**——手抄进报告的数字对不上会立刻暴露
5. 语法编译
6. **残留引用扫描**（改名/移动后有没有断链）
7. **固定层级引用扫描**（新增脚本有没有用 `../..` 定位 results，那种写法搬迁后会静默指错）
8. 工作区根目录卫生

> 第 4 项值得特别说：报告里的数字是**人抄**的，最容易出错，而且错了没人会发现。
> 用脚本把报告与 JSONL 对一遍，是把"文档准确性"也纳入自动检查。

## 关于 `_archive/`

`_archive/` 里是**开发期的内部校验脚本**：它们校验的对象是项目内部的周记录与博客草稿，
不属于这个仓库的对外内容，所以移到这里留档，不参与回归。
